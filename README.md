# FPGA 车载道路环境感知与显示系统

在 PGL25G FPGA 上实现的**纯片内**车载视觉系统：双路视频源（OV5640 摄像头 + 千兆以太网）接入 → DDR3 帧缓存 → 1024×600 LCD 显示，同时在 FPGA 内部完成红绿灯识别、车道边线检测、车辆横向状态判定与 OSD 叠加，**全程不经过 CPU/DSP**，所有算法都是 Verilog 流水线。

---

## 一、硬件平台

| 项目 | 参数 |
|---|---|
| FPGA | 紫光同创 PGL25G（LogicOS / PDS 2025.1 工具链） |
| 摄像头 | OV5640，DVP 8-bit RGB565 |
| 网络 | 千兆以太网 RGMII |
| 帧缓存 | DDR3（16-bit 数据位宽） |
| 显示 | LCD 1024×600 |
| 板卡网络 | MAC `00:11:22:33:44:55`，IP `192.168.1.10` |
| 上位机网络 | 同网段 `192.168.1.x`，默认收端 `192.168.1.102`，UDP 端口 `8080` |

## 二、系统架构

```
                    ┌──────────────┐
   OV5640 ──DVP────▶│ cam_line_pick│──▶ async_fifo ──┐
                    │ 抽取缩放      │                 │
                    └──────────────┘                 │
                                                     ├─▶ quad_wr_ctrl ─▶ DDR3 写口
                    ┌──────────────┐                 │   （扫描序合成）
   PC ──UDP/RGMII──▶│ udp_video_rx │──▶ async_fifo ──┘
                    └──────────────┘
                                                     DDR3
                                                      │
                            ┌─────────────────────────┘
                            ▼
                    ┌──────────────┐
                    │ ddr3_rw_ctrl │──▶ 像素流 ──┬──▶ LCD 1024×600
                    └──────────────┘             │
                                                 ▼
                                        ┌─────────────────────┐
                                        │ 识别旁路（只读窗口）  │
                                        │ 红绿灯 / 车道线      │
                                        │ → 决断 → OSD 叠加    │
                                        └─────────────────────┘
```

**关键设计点**

- 两路视频是**不同时钟域、不同帧率**的独立流，通过双时钟异步 FIFO（格雷码指针、FWFT 读出）汇入唯一的 DDR3 写口，由 `quad_wr_ctrl` 按扫描顺序合成整帧，避免读写冲突。
- 识别模块**不额外占用 DDR3 带宽**：它挂在读回通路的像素流上，在扫描到感兴趣窗口时顺带统计，边扫描边判决。
- 显示为 2×2 四宫格（每格 512×300），左上为摄像头，其余三格为 PC 送来的同一路视频；车道线与车态识别只在 PC 全屏模式下工作。

## 四、★ 双份源码约定（改代码前必读）

`rtl/` 与 `prj/source/rtl/` 中存在**同名副本**。PDS 工程 `eth_ddr_lcd.pds` 引用的路径是 `source/rtl/xxx.v`，也就是说：

> **PDS 编译的是 `prj/source/rtl/` 那一份，不是 `rtl/` 那一份。**

修改任何被两份同时保存的模块（如 `quad_wr_ctrl.v`）后，**必须把文件复制到另一处**，否则你改的代码根本不会进综合，现象是"改了没变化"但布局布线照样跑完，非常容易误判。

```bash
cp rtl/quad_wr_ctrl.v prj/source/rtl/quad_wr_ctrl.v
```

改完用下面这条命令核对两份是否一致（无输出即一致）：

```bash
diff rtl/quad_wr_ctrl.v prj/source/rtl/quad_wr_ctrl.v
```

## 五、编译

```bash
cd prj
pds_shell.exe -project eth_ddr_lcd.pds -run gen_bit_stream
```

产物在 `prj/generate_bitstream/`，比特流为 `.sbit`。全套流程约 4 分钟，日志中的资源数应与上表一致。

> 若通过脚本/后台方式调用 `pds_shell`，某些环境会误报 "failed" 而实际 `exit=0`，**以日志内容为准**，不要只看返回码。

## 六、仿真

```bash
cd sim
./run_reg_v32.sh
```

一键完成编译 + 全部测试台回归。当前状态：**PASS = 27，FAIL = 0**。

覆盖范围包括：UDP 命令校验（`tb_cmd_lane`，18 条断言）、车道线决断显示映射（`tb_lane_dsp`，逐像素比对 2560 px）、车道识别开关不影响检测通路（`tb_lane_off`，开关前后锚点逐位相等）、以及红绿灯、抽取缩放、DDR3 读写、四宫格合成等。

环境为 ModelSim（`/c/modulesim/win64`）。中文日志在部分环境下是 GBK 编码，查看时需转码：

```bash
iconv -f GBK -t UTF-8 reg_v32.log
```

## 七、上位机与命令协议

```bash
python pc/video_sender.py --ip 192.168.1.10 --port 8080
```

GUI 面板可切换视频源、发档位、开关车道识别显示。协议为 4 字节整包：`magic(2) + 值(1) + ~值(1)`，用取反字节做校验。

| magic | 作用 | 值域 |
|---|---|---|
| `0xA55A` | 视频源切换 | 0 = 全屏 / 1 = 四宫格 / 2 = 摄像头全屏 |
| `0xA55B` | 档位 | 0 = 空挡 / 1 = 前进 / 2 = 倒挡 |
| `0xA55C` | 车道识别显示开关 | 0 = 隐藏 / 1 = 显示（上电默认显示） |

`0xA55C` 只控制**屏幕上是否画车道线与决断灯**，识别与车态判定在后台照常运行——两种状态下内部锚点信号逐位相同，这一点有专门的测试台守着。

## 八、当前版本与已知边界

**v51** 是本仓库对应的版本，相对基线 v46 的演进：

- **v49**：决断灯四态（左/右/左右都可/直行）映射调整，把"丢线"并入"左右都能变"一类显示。
- **v50**：新增 `0xA55C` 车道开关命令，上位机面板加一键开关。
- **v51**：语义修正为"只关显示、不关识别"，撤除检测通路的门控，只保留 OSD 绘制的门控。

**诚实的边界**（写在这里是为了不被误读）：

1. 车道线与车态识别**仅在 PC 全屏模式**（1024×600 单源）下工作，四宫格与摄像头模式不启用——因为每格 512×300 时线宽不足 2 像素，统计量不够。
2. 在急弯与明显遮挡的测试序列上，约 21% 的帧判定为"丢线"（LOST）。
3. 位置先验（"车道线在画面中大致位置不变"）只能用于**排除**误检，不能用于**确认**——实测最稳定的竖线其实是引擎盖边缘，真车道线在急转时会横扫画面。
4. 系统输出的是**帧级**结果，不提供亚像素精度或连续轨迹输出。
5. 本项目不宣称吞吐量指标；PC 链路实测 24.0 fps、摄像头 22 fps，瓶颈在包间隔而非算力。

## 九、说明

- 仓库不含编译中间产物（`prj/compile/` 等）与测试视频，见 `.gitignore`。
- `doc/` 下有设计记录（`QUAD_README.md`，含逐版改动与实测数据）、答辩要点、演示脚本。
- 时序报告中存在跨时钟域路径的负 slack（WNS −2.619 ns，最差路径 `eth_rxc → sys_clk`），该路径位于异步 FIFO 的格雷码指针上，属于设计上不要求单周期收敛的伪路径；当前约束未对其声明 false path，故工具照常报出。
